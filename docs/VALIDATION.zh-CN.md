# 真机验证摘要

验证日期：2026-10-17～2026-10-19。设备：一台TB378FC，8GB/256GB，SM8750P。个人标识、地址、密码、校准和原始私有日志不随公开记录发布。

## 内部安装和双系统

1. 使用原有本机Android启动备份，不重新备份启动镜像。三件套与安装前分区SHA匹配。
2. 按所有者选择创建约80GiB Ubuntu空间并重新初始化Android数据；GPT检查、写入根系统全流SHA、ext4检查及扩容通过。
3. v4启动包补齐`15.0.0`/`2026-07`后从内部根系统启动，`findmnt`显示`/dev/sda19`为rw ext4，根overlay约80G。
4. Ubuntu→ColorOS：三个分区整分区读回SHA通过；摄像头看到系统界面，ADB `sys.boot_completed=1`、数据区约130G。
5. ColorOS→Ubuntu：KernelSU root运行安装模块中的同一切换脚本，目标三件套写入/读回通过，重启成功。
6. 新Ubuntu boot ID不同，预先保存的文件、账户密码、sudo授权和Snap enabled/active状态保留。A槽successful已置位。
7. 后续再次进入Android，提取确认KernelSU模块已激活：`enabled=true`、`action=true`、`update=false`。模块按钮的UI点击未另作独立自动化验收。

首轮内部启动约49.336秒，返回Ubuntu约45.297秒（内核3.800秒＋用户态41.497秒）。这些是systemd计时，不等于每次都保证相同开机时长。

## 公开版本与实机版本的区别

实机使用包含个人设置的私有v81三件套和根系统。公开版本重新整理源码、抽出设备绑定配置、排除固件与个人数据，完成离线检查；未经重新构建完整公开镜像后的真机回归。因此本仓库没有附带“任意同型号直接刷入即用”的承诺。

原始内核taint为4608（含外置/未签名模块），无oops位128；启动存在历史时钟告警，nftables服务也有失败记录。它们不影响本次往返结果，但不能称系统无任何告警或所有服务全通过。
